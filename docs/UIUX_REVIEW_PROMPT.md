# UI/UX 设计与审核 Prompt

这份文档用于后续改前端时保持一致标准。目标不是生成漂亮截图，而是把 `ur what u read` 做成一个高信息密度、可长期使用的个人情报终端。

## 产品设计目标

- 清晰、专业、高信息密度。
- 适合技术用户、投资研究用户、信息工作者。
- 不做普通 SaaS landing page，不堆大 hero、营销卡片、随机渐变。
- 页面要有辨识度，但不能牺牲可用性。
- 优先桌面端效率，兼顾 tablet/mobile 响应式。
- 风格参考 Linear、Readwise Reader、Perplexity、Vercel Dashboard 的清晰度，但不能照抄。
- 核心价值是帮助用户快速判断：今天什么值得读、为什么值得读、下一步怎么处理。

## 设计生成 Prompt

```text
你是一个资深前端工程师和 UI/UX 设计师。请为一个 AI-first RSS/news 聚合产品设计并实现前端页面。

产品定位：
- 这是一个个人情报终端，不是普通 RSS 阅读器。
- 列表负责快速扫描，AI 负责解释和判断，规则/来源负责个性化。
- 用户应能在 3 秒内知道今天有哪些重点，在 30 秒内知道为什么值得读。

必须满足：
- 清晰的信息架构；
- 明确的视觉层级；
- 一致的 spacing system；
- 可复用组件；
- 响应式布局；
- hover / active / focus / selected / loading / empty / error 状态完整；
- 良好的可访问性；
- 不要模板感；
- 不要过度渐变、过度阴影、过度动画；
- 不要使用随机颜色和随机间距；
- 优先桌面端效率，移动端保证可读和可操作。

技术要求：
- 使用 React；
- 使用 Tailwind CSS；
- 组件结构清晰；
- 使用语义化 HTML；
- 按钮、输入框、卡片、导航、标签、状态 badge、toolbar、list row 都要有统一风格；
- 页面在 desktop / tablet / mobile 下都要合理显示；
- 如果使用 mock data，要覆盖 loading、empty、error、selected、active、stale、failed 等状态。

设计风格：
- 现代、克制、专业；
- 类似 Linear / Readwise Reader / Perplexity / Vercel Dashboard 的清晰度；
- 但不要直接照抄；
- 要有一个和产品核心价值相关的独特设计亮点，例如 Signal、Why this matters、Storyline、Daily Briefing。

实现页面：
AI RSS 信息流 Dashboard

页面需要包含：
- 左侧来源/智能视图侧边栏；
- 顶部搜索和全局状态；
- 主阅读流；
- 筛选和排序；
- 内容列表行或卡片；
- 状态标签；
- 主要操作按钮；
- AI 速览模块；
- 空状态；
- 加载状态；
- 错误状态；
- 移动端适配。

输出：
1. 完整 React 代码；
2. 简短说明设计思路；
3. 说明这个设计如何满足现代 UI/UX 标准；
4. 明确哪些组件可以复用；
5. 明确哪些状态已经覆盖。
```

## 严格 UI/UX 审核 Prompt

```text
请你以严格的资深 UI/UX reviewer 身份审查上面的设计。

不要夸奖，不要泛泛而谈，直接指出问题。请按照真实成熟产品标准评估，而不是按照 demo 页面标准评估。

从以下维度打分，每项 1-10 分：

1. 信息架构是否清晰；
2. 视觉层级是否明确；
3. 页面是否有现代感；
4. 是否有模板感；
5. 可读性是否足够；
6. 交互是否直观；
7. 状态设计是否完整；
8. 响应式是否合理；
9. 可访问性是否达标；
10. 组件一致性是否足够；
11. 是否有产品辨识度；
12. 是否存在设计过度。

然后输出：
- 最大的 5 个 UX 问题；
- 最大的 5 个视觉设计问题；
- 哪些模块应该删减；
- 哪些模块应该强化；
- 如何修改才能更像一个真实成熟产品；
- 给出修改后的设计原则；
- 如果要重写代码，应该怎么改。

审核标准：
- 如果只是漂亮但信息层级混乱，必须扣分。
- 如果按钮、badge、chip、toolbar 风格不一致，必须扣分。
- 如果移动端只是简单堆叠而不考虑触控效率，必须扣分。
- 如果页面像通用 SaaS 模板，必须扣分。
- 如果 AI 模块只是摘要文本列表，而没有判断、优先级或上下文，必须扣分。
- 如果没有 loading / empty / error / selected / focus 状态，必须扣分。
```

## 本项目验收清单

每次前端 UI 改动至少检查以下项目：

- `desktop`：阅读流、AI 页面、管理页在宽屏下主次关系是否清楚。
- `mobile`：顶部导航、筛选按钮、文章详情 toolbar 是否可点击、不可横向撑破。
- `states`：loading、empty、error、selected、active、disabled 是否都有合理样式。
- `density`：列表是否保持高信息密度，是否避免无意义的大卡片。
- `reading`：正文行宽、行高、段距、链接、图片、代码块是否可读。
- `AI`：AI 速览是否回答“为什么值得读”，而不只是复述标题。
- `management`：管理页是否偏工具台，而不是普通表单堆叠。
- `tokens`：颜色、字体、圆角、间距是否来自统一变量，避免随机值继续扩散。
- `accessibility`：按钮有可见 focus，图标按钮有文本或 `aria-label`，交互元素键盘可达。

## 当前前端方向

- 主题：新闻白背景 + 高对比文字 + 低阴影。
- 字体：黑体/sans 体系，优先 `IBM Plex Sans` + 系统中文黑体。
- 控件：小圆角、细边线、克制 hover。
- 标签和状态：胶囊 badge，但不能滥用颜色。
- 列表：高密度行式布局，selected 用左侧强调线。
- AI：应逐步从摘要历史升级为情报判断面板。
